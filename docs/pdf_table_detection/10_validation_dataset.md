Meaning |\n| --- | --- | --- |\n| `confidence` | >= 'high' | Table area detectado con certeza |\n| `num_rows` | exact match | Número correcto de filas |\n| `num_columns` | exact match (11) | 11 columnas detectadas |\n| `warnings_count` | 0 | Sin problemas |\n| `part_no_filled_ratio` | >= 95% | Casi todos POSs tienen PART NO |\n| `measurement_filled_ratio` | >= 90% | Medidas detectadas |\n| `required_fields_filled` | >= 99% | pos, part_no, designation, qty, measurement, standard |\n\n### Category: \"problematic\" (Known Issues)\n\n| Criterion | Threshold | Meaning |\n| --- | --- | --- |\n| `warnings_include` | [specific list] | Warnings esperados para el issue |\n| `issue_detected` | true | Parser detecta el problema |\n| `after_mitigation_success` | true | Después de aplicar workaround, parse correcto |\n| `manual_intervention_needed` | true/false | Si requiere fix manual o se auto-corrige |\n\n### Category: \"edge_cases\" (Extreme)\n\n| Criterion | Threshold | Meaning |\n| --- | --- | --- |\n| `graceful_failure` | true | No crash, managed error |\n| `partial_data_extracted` | >= 50% | Al menos mitad de datos recuperados |\n| `warning_issued` | true | Usuario alertado de problema |\n\n### Category: \"regression\" (After Fixes)\n\n| Criterion | Threshold | Meaning |\n| --- | --- | --- |\n| `fix_applied_successfully` | true | Issue original corregido |\n| `no_new_failures` | true | No introdujo nuevos problemas |\n| `performance_maintained` | >= 95% | Tiempo de parse similar o mejor |\n\n## Test Execution Script (Proposed)\n\n```bash\n# Run all validation tests\nnode docs/parser-validation/validate.js\n\n# Run specific category\nnode docs/parser-validation/validate.js --category=good\n\n# Run regression tests only\nnode docs/parser-validation/validate.js --regression\n\n# Generate report\nnode docs/parser-validation/validate.js --report\n```\n\n## Expected Output\n\n```\nValidation Report -
