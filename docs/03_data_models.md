# Data Models

## 1. Engine Row Model (`engine_*.json`)

Each engine file stores an array of row objects.

### Identity and navigation fields
- `ID`: row identifier
- `PART NO.` / `pn`: part number
- `POS`: position index in page schema
- `Source Page`: page number reference
- `engine_model`: engine code
- `source_file`: source workbook/file marker

### QA revision fields
- `qa_revision_estado`: review status text
- `qa_revision_accion`: review action text
- `qa_revision_updated_at`: timestamp (ISO string)

### GESA and final normalization fields
- `gesa`: usually `SI` or `NO`
- `designation_gesa`, `dimensions_gesa`, `weight_gesa`, `units`, `norma`, `normalizado`
- `designation_final`, `measurement_final`, `weight_final`

Normalization rule highlights:
- `measurement_final` prioritizes `dimensions_gesa`; fallback is `MEASUREMENT / STANDARD`.
- spacing in measurements is collapsed to single spaces.

### Substitution/export-related fields
- `sust_hierarchie`, `sust_new_part_number`, `sust_superseded_list`
- `EN_WEB`
- image and schema pointers (`ruta_foto`, `esquemas`, `esquemas_circulos`, `ruta_esquemas_pos`, `exp_imagenes`)

## 2. Revision Keying Model

Runtime key aliases generated by `js/revision.js`:
- stable key: `idx=<global_index>`
- legacy key: `ID||PN||Page||POS||source_file`
- occurrence key: `<legacy_key>||occ=<n>`

Purpose:
- keep backward compatibility across payload versions and duplicate legacy keys.

## 3. Revision Payload Models

### v2 payload (server sync/apply)
```json
{
  "meta": {
    "updated_at": "2026-04-16T10:00:00.000Z",
    "source": "server.js",
    "version": 2,
    "rows": 123
  },
  "revisions": {
    "v": 2,
    "r": [[1, "revisado", "mantener"]],
    "k": {
      "legacy_key": {
        "estado": "revisado",
        "accion": "sustituir",
        "updated_at": ""
      }
    }
  }
}
```

### v1 export payload (frontend download format)
```json
{
  "meta": {
    "exported_at": "2026-04-16T10:00:00.000Z",
    "source": "qa_milu.html",
    "version": 1,
    "rows": 2
  },
  "revisions": {
    "idx=1": {
      "estado": "revisado",
      "accion": "mantener",
      "updated_at": "2026-04-16T10:00:00.000Z"
    }
  }
}
```

## 4. Application State Model (`js/state.js`)

Core state object:
- data collections: `allData`, `filteredData`
- pagination/sorting: `currentPage`, `pageSize`, `sortKey`, `sortAsc`
- filters map: `filters`
- UI selection: `selectedRevisionRowKey`, `rightPanelTab`
- view mode: `columnView`, `groupedVisible`
- reference sets/maps: `newPnSet`, `supersededPnSet`, `publishedMap`, `productExportPnSet`
- auxiliary arrays: `miluNewData`, `miluSupersededData`
- PDF state: `currentPdfDocument`, `currentPdfSource`, `currentPdfPageNumber`, `currentPdfRenderTask`, selection overlays
